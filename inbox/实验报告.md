# 共享单车租赁需求预测 —— 实验报告

> 课程作业 | 数据：Seoul Bike Sharing Demand (UCI) | 流程：EDA → 预处理 → 建模调优 → 30% 测试集评估
> 本报告由 01_eda.py / 02_preprocess.py / 03_train_evaluate.py 真实运行产出全部数字，可复现（random_state=42）。

## 一、问题分析

本任务为**回归问题**：给定某小时的天气与时间特征，预测该小时的共享单车租赁数量（`Rented Bike Count`，0~3556 辆/小时）。数据来自韩国首尔 2017-12-01 ~ 2018-11-30 一整年，原始 8820 行 × 14 列。

业务直觉：单车租赁由**通勤需求**（上下班时间刚性）与**休闲需求**（天气敏感）叠加。数据是小时级时间序列，但课程要求按表格回归处理（不做时序专模型），采用随机划分 30% 测试集——这会带来轻微的时间泄漏（测试集中含训练时段相邻小时），作为课程作业的可接受近似，报告在"局限"部分讨论。

## 二、探索性数据分析（EDA，图 fig1~fig4）

### 2.1 数据质量体检（关键发现：三类脏数据）

EDA 第一件事不是画分布，是**体检**。本数据被人为埋了三类脏点，若不清洗直接建模会显著伤害结果：

| 脏点 | 数量 | 处理 |
|---|---|---|
| `Seasons` 小写 `winter`、`Functioning Day` 取值 `Y`（大小写错） | 各 80 行 | 统一 Title Case / 映射 |
| 完全重复行 | 60 组 | 删除（去重后 8760 = 365×24，实锤整年完整数据被注水） |
| 目标列 -1 值（租赁量不可能为负） | 60 行 | 删除（错误记录） |

清洗后 **8700 行**进入建模。

### 2.2 目标分布（fig1）

目标显著右偏（skewness = 1.16，均值 700 > 中位数 497）：多数时段租赁量温和，通勤高峰与夏季白天出现长尾。log1p 变换后接近正态 → 预处理对目标做 log1p，改善线性模型与梯度提升的损失景观，评估时 expm1 还原。

### 2.3 时间模式（fig2）

- **小时**：典型通勤双峰——早 8 点小峰、晚 18 点主峰（均值 1478 辆，全天最高）；凌晨 0-5 点均值仅 288 辆。
- **星期**：工作日与周末差异不大（周末休闲骑行部分抵消通勤损失）。
- **月份**：6 月最高、1 月最低，冬低夏高，符合季节性直觉。

### 2.4 天气相关性（fig3）

- 皮尔逊与斯皮尔曼相关性高度一致的前列特征：**温度**（0.53/0.56）、**小时**（0.41/0.38）、太阳辐射（0.26/0.38）、露点温度（0.38/0.37）。
- 降雨/降雪相关性低但样本极稀疏（绝大多数为 0），树模型可利用稀疏非零信号。
- **共线性实证**：corr(温度, 露点温度) = 0.913 > 0.9 → 线性模型剔除露点温度（露点≈温度的冗余投影，保留它会使系数方差膨胀）；树模型对共线性稳健，保留全特征对比。

### 2.5 类别分组（fig4）

- 季节均值：夏 1027 > 秋 814 ≈ 春 725 >> 冬 226（冬差不是春的 1/3）。
- 节假日均值 495 vs 非节假日 710——节假日整体需求低三成。
- **Functioning Day=No 共 298 行（3.4%）租赁量全为 0**：这是"停运时段"而非"需求为零"。选择**保留**这些行并讨论（见 3.3），避免删行造成分布漂移，同时让模型学到"停运≈零租赁"。

## 三、数据预处理（02_preprocess.py）

### 3.1 清洗管线

修大小写 → 去重 → 删负目标，8820 → 8700 行（详见 2.1）。

### 3.2 特征工程

| 步骤 | 内容 | 理由 |
|---|---|--- 覆盖派活单要求 |
|---|---|---|
| Date 派生 | Month / DayOfWeek / IsWeekend | 捕捉月度季节性与周末效应 |
| Hour 周期编码 | sin/cos(2π·Hour/24) | 23 点与 0 点钟表相邻，原始整数会误导线性模型 |
| 类别 one-hot | Seasons(3) / Holiday(1) / Functioning Day(1)，drop_first | 无序类别不能用序数编码（会注入假排序） |
| 目标变换 | log1p(目标) | 右偏校正（2.2 实证） |
| 共线性 | 线性模型剔除露点温度 | corr=0.913（2.4 实证） |
| 标准化 | StandardScaler（线性 Pipeline 内） | 线性模型需要；树模型不敏感 |

### 3.3 Functioning Day=No 的处理决策

294 行停运时段（清洗后）租赁量恒为 0。三种可选方案：a) 全删；b) 全留；c) 留行但对测试指标另报"运营时段子集指标"。本作业选 **b) 保留**：这些行是真实业务状态，删行会让模型永远见不到"停运"场景，部署后遇到停运时段会给出荒谬预测；one-hot 的 Functioning Day_Yes 列让树模型轻松学到"FD=No → 0"。报告中补充讨论：保留方案对指标是"保守"的（若 FD=No 行全预测正确，RMSE 不受损），且 FD=No 在测试集中占比与训练集一致（3.4%），无分布偏移风险。

### 3.4 数据划分

train_test_split(test_size=0.30, random_state=42)：训练 6090 / 测试 2610 行。测试集全程隔离，仅在 03 的最终评估使用一次，不参与任何调参决策。

## 四、建模与调优（03_train_evaluate.py）

### 4.1 模型阵容与理由

| 模型 | 角色 | 选型理由 |
|---|---|---|
| LinearRegression | 基线 | 可解释、快，建立参照系 |
| Ridge | 基线+正则 | L2 抑制共线性下的系数爆炸 |
| Lasso | 基线+正则 | L1 稀疏化，兼作特征筛选观察 |
| RandomForest | 主力 | 非线性+交互自动捕捉 |
| XGBoost | 主力 | 梯度提升，表格数据强基线 |
| 模型对比 | — | 线性 vs 树、集成 vs 集成 |

（LightGBM 同为主力，见 4.2 表。）

### 4.2 调参策略与纪律

- RandomizedSearchCV，搜索空间对每个模型取关键维度（Ridge/Lasso 的 alpha 对数尺度网格 20 点；RF 树深/叶子/特征子采样 15 组；XGB/LGB 学习率/深度(叶子)/采样/正则 20 组）。
- 所有搜索在**训练集内 5 折 CV**（KFold shuffle=True, random_state=42，全模型共用同一折结构，保证公平）。
- **测试集零参与**：每步只用训练集 CV 选参，测试集只在全部模型定型后评估一次。
- 训练目标为 log1p 空间，CV 指标为 log-RMSE；测试集指标在**原始量纲**计算（expm1 还原 + clip(0) 非负截断）。

## 六、局限与改进方向

1. **随机划分的时间泄漏**：按课程要求随机划分，测试集含训练时段相邻小时，指标偏乐观；严格做法是时序前向验证（train: 2017-12~2018-09，test: 2018-10~11）。改进：滚动起点验证。
2. **单城市单年数据**：特征泛化到其他城市/年份需谨慎（一年数据未覆盖跨年气候异常）。
3. **未做时序特征**：未构造滞后特征（t-1 小时租赁量）与滑窗统计——它们通常是时序数据最强特征，但随机划分下会造成严重泄漏，与时序验证配套引入才有意义。
4. **模型上限**：未尝试 CatBoost / 神经网络（MLP/1D-CNN）；LightGBM/XGBoost 已达课程要求。
5. **FD=No 行的处理**：保留但未做子集指标；生产场景应分"停运检测"与"运营时段需求"两阶段建模。
